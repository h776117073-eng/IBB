## 2. هيكل الملفات المعماري المرتبط بالخطة

| المسار / الملف في الفرع `feat/ibb-market-map-engine` | الدور الهندسي والوظائف المنفذة |
| :--- | :--- |
| `sql/01_postgis_26_tables_schema.sql` | مخطط PostgreSQL + PostGIS الكامل للـ **26 جدولاً** مع فهارس `GIST`، ونوع التعداد `map_record_status` (`RAW`, `PENDING_REVIEW`, `VERIFIED`, `REJECTED`, `PUBLISHED`, `ARCHIVED`)، وسياسات الأمان `RLS`. |
| `sql/02_seed_and_import_pipeline.sql` | إجرائية الاستيراد الذرية القابلة للتكرار (Idempotent Import) لبيانات محافظة إب، مديرياتها الـ 20، أحياء مدينة إب، الشوارع، المباني، المعالم، المتاجر (`merchants` & `merchant_locations`)، وإصدار إحصاءات تقرير الاستيراد. |
| `sql/03_map_api_rpc_functions.sql` | الدوال المكانية الخلفية في Supabase التي تخدم نقاط النهاية الـ 20 (`/api/map/*`) بما فيها البحث المتقدم، تفاصيل المتجر، اعتماد/رفض المساهمات، والبلاغات. |
| `js/ibb-api-service.js` | طبقة واجهات البرمجة الموحدة (`IbbMapApiService`) التي تنفذ جميع عقود الـ API العشرين (`GET/POST/PATCH /api/map/*`) مع التحقق من المدخلات، وتحديد الصلاحيات (`contributor`, `reviewer`, `admin`, `merchant`)، والتخزين المؤقت، وسجل التدقيق. |
| `js/ibb-search-worker.js` | محرك البحث المكاني المتقدم: دعم العربية والإنجليزية، التسامح مع الأخطاء الإملائية (`Levenshtein Edit Distance <= 2`)، قاموس المرادفات التجارية في إب، الاقتراح الفوري، والترتيب المركب (المسافة + الملاءمة + الشعبية + التقييم). |
| `js/ibb-routing-worker.js` | محرك التوجيه والملاحة المزدوج: مسارات السيارات، مسارات المشاة المستقلة (الأزقة والسلالم والطرق الجبلية مع خيارَي **الطريق الأقصر** و**الطريق الأسهل** الأقل انحداراً)، دعم النقاط الوسيطة (`Waypoints`)، والمسارات البديلة، بالإضافة إلى مرشح `KalmanGPSFilter` وخوارزمية `Map Matching` وكشف الانحراف (`Off-Route Rerouting`). |
| `js/ibb-store-integration.js` | وحدة التكامل الثنائي الاتجاه مع **إب ماركت (`IBB Market`)**: بطاقة المتجر السفلية، صفحة المتجر الكاملة (`/store/{merchant_id}`) المحملة من قاعدة البيانات (الغلاف، الشعار، المنتجات، التصنيفات، الأسعار، التوفر، المراجعات، أوقات العمل)، العودة للخريطة مع حفظ الحالة، وبوابة التاجر لتحريك الدبوس وتحديد المدخل ورسم مضلع منطقة الخدمة (`delivery_zone_polygon`). |
| `js/ibb-contributions-admin.js` | نظام المساهمات المجتمعية (إضافة/تعديل مكان، رسم شارع/ممر `LineString`، رسم مبنى `Polygon`، رفع الصور والمراجعات، نقاط وشارات المساهمين)، نظام البلاغات الـ 9، ولوحة إدارة جودة البيانات (`RAW` / `PENDING_REVIEW` / `VERIFIED` / `REJECTED` / `PUBLISHED` / `ARCHIVED`) مع مقارنة القديم والجديد. |
| `js/app.js` & `index.html` & `css/style.css` | ربط محرك العرض `MapLibre GL JS` بتجميع العلامات (`Clustering`)، لوحة التحكم بالـ 15 طبقة، شاشة الاستكشاف (`Explore` — 17 تصنيفاً)، وضع القيادة ملء الشاشة (`Driving Mode HUD`)، تتبع المندوب والطلب لحظياً (`Live Courier Tracking`)، ومدير الخرائط دون اتصال مع حساب المساحة والحذف. |
| `tests/map_28_acceptance_suite.js` | حزمة الاختبارات الآلية الشاملة التي تختبر جميع البنود الـ 28 المطلوبة وتصدر تقرير نتائج موثقاً. |

## 3. مراحل التنفيذ التسع (Execution Phases)

### المرحلة الأولى: التدقيق الهندسي (مكتملة 100%)
* فحص المستودعات والفروع وقاعدة بيانات Supabase وأرشيفات `PMTiles` والشظايا والموسوعة الهندسية `PDR`، وإصدار الملفات الثلاثة: `MAP_CURRENT_STATE_AUDIT.md`، و`MAP_GAP_ANALYSIS.md`، و`MAP_IMPLEMENTATION_PLAN.md`.

### المرحلة الثانية: قاعدة البيانات الجغرافية واستيراد البيانات الموثقة (PostGIS 26 Tables)
* تفعيل امتداد `postgis` و`pg_trgm` في مشروع Supabase (`gdgtwonxbujgxfiqivvp`).
* إنشاء الجداول الـ 26 المستقلة مع فهارس `GIST` المكانية وحالات التحقق الست (`RAW`, `PENDING_REVIEW`, `VERIFIED`, `REJECTED`, `PUBLISHED`, `ARCHIVED`).
* تنفيذ استيراد البيانات الموثقة (اليمن، محافظة إب، الـ 20 مديرية، الأحياء، الشوارع، المباني، المعالم، المتاجر ومنتجاتها) مع تسجيل مصدر كل سجل في `map_sources` واستخراج أرقام تقرير الاستيراد الفعلي.

### المرحلة الثالثة: محرك الخريطة والطبقات الـ 15 وتجميع العلامات (Map Engine & Layers)
* تفعيل `Clustering` التلقائي للعلامات المتقاربة وفصلها عند التقريب.
* بناء نظام التحكم المستقل لتشغيل وإيقاف الـ **15 طبقة** (الطرق، المباني، المتاجر، المطاعم، الخدمات، المعالم، الأحياء، الحدود الإدارية، التضاريس، الارتفاعات، المسارات، حركة المستخدم، مناطق خدمة المتاجر، نقاط التوصيل، نقاط الاهتمام) إلى جانب أنماط العرض الأربعة (`Default`, `Satellite`, `Terrain`, `3D`).

### المرحلة الرابعة: نظام البحث المكاني المتقدم والاستكشاف (`Search & Explore`)
* ترقية عامل البحث لدعم العربية والإنجليزية، الأخطاء الإملائية الشائعة، المرادفات، والبحث داخل المنطقة المرئية.
* بناء واجهة `Explore` بالـ **17 تصنيفاً** مع الفرز حسب القرب أو التقييم.

### المرحلة الخامسة: التكامل العميق مع متاجر إب ماركت (`/store/{merchant_id}`)
* ربط `merchant_id` ↔ `store_id` ↔ `map_place_id` ↔ `location_id` في قاعدة البيانات والواجهة.
* بناء بطاقة المتجر السفلية وصفحة المتجر الكاملة (`/store/{merchant_id}`) المحملة مباشرة من Supabase، مع التكامل ثنائي الاتجاه (`الخريطة ↔ المتجر`) وحفظ حالة الكاميرا والبحث عند الانتقال والعودة.
* بناء أداة التاجر لتحديد موقع متجره، تحريك الدبوس، تحديد المدخل، ورسم مضلع منطقة الخدمة (`delivery_zone_polygon`).

### المرحلة السادسة: تحديد الوجهة والملاحة للسيارات والمشاة والتتبع الحي
* دعم النقاط الوسيطة (`Waypoints`: إضافة، حذف، إعادة ترتيب) وعرض المسارات البديلة والفروقات بينها.
* بناء نظام ملاحة السيارات بمرشح `Kalman Filter` و`Map Matching` وإعادة الحساب عند الانحراف (`Rerouting`) ووضع القيادة ملء الشاشة (`Driving Mode`) والنطق الصوتي العربي.
* بناء محرك ملاحة المشاة المستقل للأزقة والسلالم والطرق الجبلية مع خيارَي **الطريق الأقصر** و**الطريق الأسهل** (الأقل انحداراً).
* إضافة تتبع الموقع المباشر ومتابعة المندوب والطلب لحظياً مع تقدير زمن الوصول (`ETA`).

### المرحلة السابعة: المساهمات المجتمعية، البلاغات، ولوحة إدارة جودة البيانات
* تمكين إضافة مكان، تعديل مكان، رسم شارع/ممر (`LineString`)، رسم مبنى (`Polygon`)، رفع الصور والمراجعات، ونظام النقاط والشارات.
* بناء نظام البلاغات الـ 9 (متجر مغلق، موقع خاطئ، شارع غير موجود، طريق مغلق، اسم غير صحيح، مكان مكرر، معلومات غير صحيحة، صورة غير مناسبة، مكان لم يعد موجوداً).
* بناء لوحة إدارة جودة البيانات (`Admin Moderation Console`) لمراجعة التعديلات ومقارنة القديم بالجديد واعتمادها أو رفضها وفق الحالات الست (`RAW`, `PENDING_REVIEW`, `VERIFIED`, `REJECTED`, `PUBLISHED`, `ARCHIVED`).

### المرحلة الثامنة: الخرائط دون اتصال (`Offline Maps`) وواجهات `/api/map/*`
* ترقية مدير الخرائط دون اتصال لتحديد المنطقة ومستوى التفاصيل وحساب الحجم والتنزيل والحذف وإدارة المساحة.
* إكمال طبقة واجهات الـ API الـ 20 (`GET/POST/PATCH /api/map/*`) مع صلاحيات الأدوار وسجل التدقيق.

### المرحلة التاسعة: تنفيذ الاختبارات الـ 28 والنشر على فرع التطوير المستقل
* تشغيل حزمة الاختبارات الـ 28 الموثقة (`tests/map_28_acceptance_suite.js` + فحوصات Supabase الحية).
* رفع جميع التحديثات إلى الفرع المستقل `feat/ibb-market-map-engine` على GitHub والتحقق الحي من جميع الوظائف.
