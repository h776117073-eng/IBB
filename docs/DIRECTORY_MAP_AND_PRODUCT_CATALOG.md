# دليل إب والخريطة والكتالوج — عقد التنفيذ

## أنواع الكيانات

تُخزن كل نقطة في \`directory_places\` بنوع واضح:

- \`BUSINESS\`: متجر أو منشأة تجارية، ويمكن أن تملك صفحة متجر.
- \`LANDMARK\`: جامع أو مسجد أو معلم تاريخي أو حديقة.
- \`STREET\`: شارع أو طريق أو جسر أو دوار.
- \`NEIGHBORHOOD\`: حي أو حارة أو قرية أو عزلة.
- \`PUBLIC_SERVICE\`: مستشفى أو مدرسة أو مرفق عام.
- \`OTHER\`: عنصر يحتاج تصنيفًا يدويًا.

المعلم والشارع والحي يظهر على الخريطة، لكنه لا يتحول تلقائيًا إلى متجر أو مخزون.

## الثقة والموقع

التحقق من الاسم منفصل عن التحقق من الإحداثيات. لا يظهر العنصر على الخريطة العامة إلا عندما يكون \`verification_status=VERIFIED_MATCH\` و\`visibility_status=PUBLISHED\` وتتوفر إحداثيات صالحة أو هندسة GeoJSON صالحة. لا يُستنتج موقع دقيق من اسم المنشأة وحده.

حقول \`location_precision\`:

- \`EXACT\`: إحداثيات صريحة موثقة أو نقطة مصدر واضحة.
- \`APPROXIMATE\`: مركز Plus Code أو نتيجة عنوان تقريبية؛ تُعرض بعلامة تقريبية.
- \`MISSING\`: لا توجد إحداثيات صالحة؛ يبقى السجل في الدليل ولا يرسم دبوسًا.

تكرار Google Place ID مسموح؛ فهو ليس مفتاح المنشأة ولا يُستخدم لإزالة الفروع المتشابهة.

## واجهة الخريطة

واجهة الخريطة تستخدم نطاق العرض (bbox) والـzoom لتجلب البيانات المطلوبة فقط. عند التصغير يعيد API عناقيد محسوبة من قاعدة البيانات؛ وعند التكبير يعيد نقاطًا مفصلة. يدعم البحث والفلاتر حسب نوع الكيان والفئة، ويعرض روابط فتح الموقع والاتجاهات في Google Maps. طبقة الأساس OpenStreetMap مع الإسناد الإلزامي؛ روابط Google Maps لا تعني استخدام بلاطات Google.

## الكتالوج العام مقابل مخزون التاجر

\`catalog_products\` مكتبة مرجعية عالمية، وليست مخزونًا محليًا. تُربط بالمتجر عبر \`store_catalog_suggestions\` مع درجة تطابق وسبب الاقتراح. يظهر المنتج في قسم «اقتراحات من المكتبة» مع توضيح أنه غير مؤكد من التاجر. لا يتحول إلى منتج فعلي أو سعر أو مخزون إلا بعد تأكيد التاجر وإنشاء سجل مستقل في \`products\`.

## الصور

مفتاح الصورة القياسي \`products/{barcode}.webp\` داخل R2. يُزال EXIF، ويُحدّ الحجم إلى 320×320، ويُحفظ WebP بجودة مناسبة للاتصال الضعيف. تستخدم الصور Cache-Control طويلًا ومفتاحًا ثابتًا. صورة غير موجودة أو غير مطابقة للباركود لا تُعرض.

## التوسع

D1 مناسب للنسخة الأولى داخل مدينة واحدة مع فهارس bbox واسم/فئة. قبل التوسع إلى مدن ومحافظات كثيرة أو تشغيل طلبات/دفتر مالي، ينقل مخزن البيانات المكاني والمعاملات إلى PostgreSQL/PostGIS؛ يبقى Worker طبقة API على الحافة وR2 للوسائط. لا يُفعّل الدفع قبل إضافة مزود محلي واختبار التسوية.
