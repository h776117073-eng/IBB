# خطة تنفيذ PDR — المرحلة الأولى

## الهدف

بناء تجربة عميل أولية يمكن اختبارها على الهاتف، متصلة ببيانات الكتالوج المعتمدة فقط، مع إبقاء الموقع الحالي كما هو وعدم تشغيل معاملات مالية غير جاهزة.

## نطاق الدفعة الأولى

| ميزة | مرجع PDR | التنفيذ في هذه الدفعة |
|---|---|---|
| الصفحة الرئيسية والاستكشاف | SCR-CUST-004 | واجهة عربية RTL متجاوبة |
| الفئات | SCR-CUST-005 | تصفية محلية واضحة |
| البحث النصي | SCR-CUST-009 | بحث في المنتجات والمتاجر المعتمدة |
| بطاقات المنتجات والسعر | SCR-CUST-010 | قراءة API مع حالة فارغة عند عدم وجود بيانات |
| المتاجر | SCR-CUST-011 | عرض بيانات المتجر المعتمد مع تمييز مراجعة البيانات عن توثيق الملكية |
| السلة | SCR-CUST-012 | واجهة محلية للمعاينة فقط، دون إنشاء طلب |

## ما هو خارج النطاق الآن

- تسجيل دخول OTP أو تحقق بيومتري.
- تحديد موقع GPS إجباري أو مضلعات PostGIS.
- بحث بالصورة وذكاء اصطناعي حواري؛ لن تظهر كميزات عاملة قبل وجود خدمة حقيقية.
- الدفع الإلكتروني أو Escrow أو المحفظة أو التسوية.
- إنشاء الطلبات أو حجز المخزون.
- تتبع مندوب حي أو محادثة/اتصال.
- بيانات تجريبية موهومة أو تقييمات وتوفر وتوقيت توصيل غير موثوق.

## الملفات المضافة

- market/index.html: الهيكل الدلالي وتجربة العميل.
- market/styles.css: الهوية المرئية والاستجابة للهاتف والحاسوب.
- market/app.js: قراءة API، البحث، الفئات، البطاقات والسلة المحلية.
- docs/PDR_YEMEN_ADAPTATION.md: قرارات المواءمة المحلية.

## اختبارات القبول المطلوبة قبل دمجها في المسار الرئيسي

1. فتح market/ على عرض هاتف 360px و390px دون تمرير أفقي.
2. فتحها على شاشة حاسوب 1280px دون تراكب العناصر.
3. مع اتصال API: عرض المتاجر والمنتجات المنشورة فقط.
4. مع API يعيد قوائم فارغة: ظهور رسالة واضحة وعدم اختلاق منتجات.
5. مع تعذر API: ظهور رسالة اتصال مع بقاء الصفحة قابلة للاستخدام.
6. البحث بالعربية وتصفية الفئة ثم مسح الفلاتر.
7. إضافة منتج إلى السلة وزيادة/تقليل الكمية وحساب الإجمالي عندما تكون الأسعار رقمية.
8. سعر مفقود: عدم احتسابه في الإجمالي وعدم إظهار إجمالي مضلل.
9. السلة لا تنفذ طلبًا ولا تتصل بوسيلة دفع.
10. اختبار لوحة المفاتيح، تسميات الأزرار، التباين وتقليل الحركة.

## نتيجة فحص API الفعلية

في 2026-11-02 تم فحص الخدمة من الخادم:
- عنوان الكتالوج الصحيح: https://ibb-market-api.aicreativestudio.workers.dev
- فحص الصحة: HTTP 200 وقاعدة البيانات متصلة.
- GET /api/v1/stores و GET /api/v1/products: HTTP 200، لكن القائمتين فارغتان حاليًا.
- CORS يقبل أصل https://h776117073-eng.github.io.
- عنوان ibb-market-edge خدمة مختلفة، ولا يقدّم مسارات الكتالوج هذه؛ لذلك تم تصحيح عنوان API في واجهة العميل.

النتيجة: مسار الاتصال الصحيح متاح، لكن لا توجد سجلات متاجر أو منتجات معتمدة ليتم عرضها الآن. يجب إدراج بيانات تجارية موثقة قبل توقع ظهور بطاقات فعلية.

## بوابة مساهمات التاجر — الدفعة التالية

أضيفت واجهة `market/merchant/` لإرسال بيانات نشاط المتجر والمنتجات للمراجعة عبر مسارات API الحالية:
- `POST /api/v1/submissions/stores` مع إحداثيات ومفتاح Idempotency.
- `POST /api/v1/submissions/products` لمنتج مرتبط باسم متجر معتمد.
- تحديد الموقع لا يبدأ تلقائيًا؛ يتطلب ضغط المستخدم على زر الموقع.
- توضح الواجهة أن المساهمات تبقى معلقة حتى مراجعة الإدارة، وأنها ليست حساب تاجر أو نظام مخزون وطلبات.
- أضيف رابط مباشر للبوابة من واجهة العميل.
- تمت إضافة فحوص static للبوابة ضمن ملف CI نفسه.

هذه الخطوة لا تنشئ تسجيل دخول تاجر أو توثيق ملكية أو صلاحية تعديل سجل قائم. لا يمكن للتاجر إدارة مخزونه أو استقبال طلبات حتى يتم بناء المصادقة والصلاحيات وواجهات الإدارة.

## استكمال تجربة العميل

تمت إضافة:
- نافذة تفاصيل المنتج من بيانات الكتالوج المعتمدة.
- نافذة ملف المتجر مع طلب المنتجات من مسار `GET /api/v1/stores/:id/products`.
- فتح بطاقات المتاجر بالنقر أو لوحة المفاتيح.
- تصفية المنتجات بحسب المتجر من داخل ملفه.
- تحديث البحث ليشمل أسماء المتاجر أيضًا.
- إبقاء السلة تجريبية وعدم تحويلها إلى طلب فعلي.

لا يمكن اختبار نتيجة كتالوج متجر بعينه حتى تعتمد الإدارة متجرًا ومنتجات له في قاعدة البيانات. لا تزال صفحات الحساب وتسجيل الدخول والدفع والتتبع خارج هذه الدفعة.

## نتائج الربط والاختبار — 2 نوفمبر 2026

- تم ربط فحص إمكانية الوصول عبر BrowserStack وإجراء مسح WCAG 2.1 AA للعميل والتاجر.
- فحص العميل قبل إصلاح التباين: 24 ملاحظة تباين. بعد تحديث درجات النصوص والألوان: 18 ملاحظة، وجميعها موسومة `needs_review` لأن المحرك لم يحسم تباين الرموز الزخرفية؛ لا تُعامل هذه العناصر كإخفاقات WCAG مؤكدة دون مراجعة بشرية.
- فحص التاجر قبل الإصلاح: 13 ملاحظة (10 تباين و3 autocomplete). بعد الإصلاح: 7 ملاحظات رموز زخرفية فقط، وكلها `needs_review`. تمت إضافة autocomplete مناسب/إيقاف الإكمال التلقائي للحقول غير القياسية.
- كشف اختبار المتصفح أن Worker كان يرفض نطاق Cloudflare Pages بسبب قائمة CORS القديمة. تم تحديث كود Worker المنشور مع الإبقاء على binding السر الإداري وD1، وإضافة النطاق الرسمي ونطاقات معاينة المشروع المحددة فقط.
- اختبار الإنتاج: `/api/health`, `/api/v1/stores`, `/api/v1/products` ترجع HTTP 200 من نطاق Cloudflare Pages مع Access-Control-Allow-Origin صحيح.
- اختبار Preview: نطاق المعاينة المخصص للمشروع مقبول؛ نطاق خارجي غير مصرح به يرجع HTTP 403.
- اختبار OPTIONS لطلبات المتجر والمنتج يرجع 204، وطلبات POST ذات الحمولة الفارغة ترجع 400 برسالة تحقق متوقعة دون إنشاء سجل.
- قاعدة D1 متصلة، لكن واجهات المتاجر والمنتجات ترجع حاليًا قوائم فارغة. لا توجد بيانات متاجر/منتجات معتمدة ظاهرة بعد؛ يجب إدخال البيانات ومراجعتها إداريًا قبل ظهورها للعميل.
- معاينة الواجهة التي تم اختبارها: `https://d4e5daf0.ibb-market.pages.dev/market/` وبوابة التاجر `https://d4e5daf0.ibb-market.pages.dev/market/merchant/`.
- نسخة المعاينة وليست نسخة الإنتاج؛ لم يتم تغيير نشر `main` أو ترقية المعاينة إلى الإنتاج ضمن هذه الدفعة.


## دفعة تشغيلية بعد استيراد أرشيف الدليل — 8 نوفمبر 2026

تمت إضافة مسار قراءة إداري محمي لمراجعة مرشحي الأرشيف المستورد قبل اتخاذ أي قرار نشر:

- `GET /api/v1/admin/directory/candidates` يتطلب `ADMIN_API_KEY` عبر ترويسة `Authorization: Bearer`؛ الطلبات غير المصرح بها تعيد 401.
- مصدر القائمة مقيد بالسجلات المستوردة من `GOOGLE_MAPS_ARCHIVE_WORKBOOK` التي ما زالت `UNVERIFIED` و`NEEDS_REVIEW`.
- يدعم الفرز حسب صندوق إب الجغرافي التقريبي، وخارج الصندوق، والسجلات التي لا تملك إحداثيات، أو جميع المرشحين. يدعم أيضًا البحث والصفحات.
- تُعرض بيانات المصدر ورقم Place ID والهاتف والعنوان والإحداثيات لتسهيل المقارنة اليدوية، مع رابط بحث خارجي في Google Maps. الرابط أداة مساعدة ولا يعد إثباتًا لصحة السجل.
- صفحة `admin-directory.html` لا تحفظ مفتاح الإدارة، ولا توفر أزرار نشر أو تعديل. هي للقراءة والفرز فقط.
- لا يتم تغيير حالات السجلات أو نشر أي من المرشحين تلقائيًا. يجب أن تسبق أي آلية اعتماد سياسة تحقق وسجل تدقيق مخصص ومراجعة بشرية.
- نطاق إب المستخدم للتصفية مستطيل جغرافي تقريبي `13.82–14.08 N, 44.05–44.32 E`، وليس مضلعًا إداريًا رسميًا. الحالات التي بلا إحداثيات لا تُصنّف تلقائيًا على أنها داخل المدينة.

### بوابة القبول لهذه الدفعة

1. رفض الوصول إلى قائمة المرشحين دون مفتاح إدارة صالح.
2. عدم إرجاع أي مصدر خارج أرشيف الملف المستورد أو أي حالة غير `UNVERIFIED/NEEDS_REVIEW`.
3. فصل المرشحين داخل الصندوق الجغرافي التقريبي عن المواقع الخارجية وعن السجلات التي لا تملك إحداثيات.
4. تقييد النتائج إلى 50 سجلًا كحد أقصى في الصفحة مع ربط قيم البحث كمعاملات SQL.
5. بقاء جميع سجلات الأرشيف دون تعديل أو نشر أثناء استخدام اللوحة.

هذه الدفعة لا تستبدل المراجعة البشرية ولا تُثبت الملكية أو حالة التشغيل أو توافر المنتجات.
